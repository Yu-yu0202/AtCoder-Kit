# AtCoder-Kit の使い方
AtCoder-Kit を使用するための基本的な手順を説明します。

## 1. ログイン
ほとんどの機能がログインを必要とします（例: 進行中のコンテストのダウンロード、コードの提出など）。
最初に、以下のコマンドで AtCoder-Kit にログインしてください。
```shell
ackit login
```
このコマンドを実行すると、REVEL_SESSION の入力を求められます。

REVEL_SESSION の取得方法については、[こちら](./Ex01-REVEL_SESSIONの取得.md) を参照してください。

## 2. テンプレートの設定
AtCoder-Kit では、サンプルテストや提出の際にテンプレートを利用しています。
テンプレートの作成は、`ackit template new` コマンドで行えます。
```shell
ackit template new <テンプレート名> <提出ファイル> <実行コマンド> [--compile-command <コンパイルコマンド>] [--pre-submit <提出前コマンド>] [--default]
```
- `<テンプレート名>`: テンプレートの名前を指定します。
- `<提出ファイル>`: コード提出時に使用するファイル名を指定します。
- `<実行コマンド>`: サンプルテスト時に使用するコマンドを指定します。
- `--compile-command <コンパイルコマンド>`: サンプルテスト前にコードをコンパイルする場合、そのコマンドを指定します。
- `--pre-submit <提出前コマンド>`: 提出前にソースコードを生成・変換するコマンドがある場合、そのコマンドを指定します。
- `--default`: このテンプレートをデフォルトのテンプレートとして設定します。

各コマンドはシェルスクリプトとしてではなく、実行ファイル名と引数へ分割して直接起動されます。パイプ、リダイレクト、環境変数代入、`exit`などのシェル組み込みコマンドは利用できません。必要な処理はスクリプトファイルに記述し、そのスクリプトを実行コマンドとして指定してください。

テンプレート名には単一のディレクトリ名を、提出ファイルにはテンプレートディレクトリ内の相対パスを指定してください。絶対パスや`..`を含むパスは安全のため拒否されます。

### 例 (C++・デフォルト設定):
```shell
ackit template new my-cpp-template main.cpp ./a.out --compile-command "g++ main.cpp -o a.out" --default
```
C++ はコンパイル言語であるため、`--compile-command` オプションでコンパイルコマンドを指定します。

### 例 (Python・デフォルト設定):
```shell
ackit template new my-python-template main.py "python main.py" --default
```
Python はインタプリタ言語であるため、`--compile-command` オプションは不要です。

### 例 (Rust・デフォルト設定)
```shell
ackit template new my-rust-template src/main.rs "cargo run" --default
# または:
ackit template new my-rust-template src/main.rs target/release/my-rust-template --compile-command "cargo build --release" --default
```
Rust はコンパイル言語ですが、`cargo run` コマンドを実行コマンドとして指定することで、コンパイルと実行を同時に行うことができます。

このコマンドを実行すると、テンプレートが作成され、テンプレートが保存されているディレクトリが表示されます。

そこにアクセスし、自由にテンプレートを作成できます。

### コピーしないファイルの設定

新しく作成したテンプレートには、空の `.ackitignore` が含まれます。このファイルにパターンを記述すると、コンテストのダウンロード時に一致したファイルやディレクトリを問題ディレクトリへコピーしません。

```gitignore
# Rustのビルド成果物
target/

# 一時ファイル
*.tmp
*.log

# 除外したテキストファイルのうち、README.txtだけはコピーする
*.txt
!README.txt
```

パターンはテンプレートディレクトリを基準に、gitignoreと同じ形式で評価されます。空行、`#`から始まるコメント、`*`、`?`、`**`、ディレクトリ末尾の`/`、テンプレートルートを表す先頭の`/`、除外を取り消す先頭の`!`を使用できます。大文字・小文字は区別されます。

ディレクトリ自体を除外すると、その配下は走査されません。配下の一部を`!`で再びコピー対象にする場合は、たとえば`generated/*`で中身を除外してから`!generated/keep.txt`を指定してください。

`.ackitignore`自体とテンプレート直下の`problem.json`はコピーされません。`template.json`はサンプルテストと提出に必要なため、パターンに一致しても常にコピーされます。`.ackitignore`がない場合は、この除外対象を除いてテンプレート内のすべてのファイルがコピーされます。

## 3. コンテストのダウンロード
コンテストをダウンロードするには、以下のコマンドを実行します。
```shell
ackit download <コンテストID> [--problem <ラベル>] [--template <テンプレート名> | --no-template]
```
- `<コンテストID>`: ダウンロードしたいコンテストの ID を指定します（例: `abc123`, `arc123`, `awc1234`）。
- `--problem <ラベル>`（`-p`）: AtCoder の問題一覧に表示されるラベルを指定すると、その問題だけをダウンロードします。`A` と `a` は同じラベルとして扱います。省略すると全問をダウンロードします。
- `--template <テンプレート名>`: サンプルテストや提出の際に使用するテンプレートの名前を指定します。省略した場合、設定されていればデフォルトのテンプレートが使用されます。
- `--no-template`: ダウンロード時にテンプレートを適用しない場合に指定します。`--template` オプションと同時に指定することはできません。

現在、ABC・ARC・AGC などの主要なコンテストに加え、一部の常設コンテスト （例: `practice`） や、ベータ版である AtCoder Weekday Contest（例: `awc1234`）に対応しています。

```shell
ackit download abc485              # 全問をダウンロード
ackit download abc485 --problem A  # A だけを ./abc485_a/ に保存
ackit d abc001 -p a --no-template   # A だけを ./abc001_1/ に保存
```

単独取得では、問題一覧のリンクに含まれる問題 ID をディレクトリ名として使います。カレントディレクトリ直下に `./abc485_a/problem.json` のように保存し、選択したテンプレートも同じディレクトリに展開します。同名の保存先がある場合はエラーになります。

全問取得では、カレントディレクトリに以下の形式でファイルが作成されます。
```text
<コンテストID>/
├── contest.json
├── a/
│   ├── problem.json
│   ├── template.json
│   └── (解答用ファイルなど)
└── b/
    ├── problem.json
    ├── template.json
    └── (解答用ファイルなど)
```
`contest.json` にはコンテストの ID・タイトル・種別と、問題ラベルごとの相対パス（例: `"A": "a/problem.json"`）が入ります。各 `problem.json` には問題の ID、コンテスト ID、ラベル、タイトル、URL、実行制限、サンプルが入ります。以降、`a` や `b` などのディレクトリを「問題ディレクトリ」と呼びます。

全問取得・単独取得ともに、`--no-template` を指定した場合や使用するテンプレートがない場合も、取得した問題のディレクトリと `problem.json` が作成されます。`template.json` や解答用ファイルなどは、テンプレートが選択された場合にだけ展開されます。

`test`・`run`・`prepare`・`copy`・`submit` は、問題ディレクトリの `problem.json` と `template.json` を読み込みます。`problem.json` があれば親の `contest.json` は不要です。`problem.json` がない場合は、従来どおり `contest.json` に埋め込まれた問題情報を読み込むため、既存の解答ディレクトリは移行せずに使えます。`problem.json` が存在して読み込めない場合はエラーになります。

## 4. サンプルテスト
サンプルケースを利用してテストを行うには、以下のコマンドを実行します。

なお、問題ディレクトリで実行し、かつ `template.json` が存在する必要があります。
```shell
ackit test [--case N] [--metrics]
```

オプションを省略すると全サンプルを実行します。`--case N` は 1 から始まる番号で 1 ケースだけを選びます。`ackit t` も使用できます。`--metrics` を指定すると、各ケースの経過時間、CPU の user/system 時間、ピークメモリ使用量（bytes）を表示します。

各ケースの表示時間は `max(経過時間, CPU user 時間 + CPU system 時間)` です。実行したケースについて min/avg/max を表示し、max が AtCoder の最終実行時間に最も近い目安です。CPU 時間を取得できないケースが 1 つでもある場合は、全ケースを経過時間で集計し、`real only` と表示します。通常表示ではメモリ使用量を省略します。

サンプル実行は問題の実行時間制限に 2 秒を加えた時間で打ち切られます。コンパイルと提出前コマンドの制限時間は 120 秒です。各コマンドの標準出力と標準エラー出力は、過大なメモリ消費を防ぐためそれぞれ 16 MiB まで保存されます。

## 現在の解答を実行

問題ディレクトリで現在の解答をコンパイルして実行します。

```shell
ackit run [--input FILE]
```

`--input FILE` を指定すると、そのファイルを標準入力に渡します。相対パスは `ackit` を起動したディレクトリから解決します。省略すると起動元の標準入力を引き継ぎます。解答の標準出力と標準エラー出力はそのまま表示され、サンプルとの照合や 16 MiB の出力制限は適用されません。コンパイルエラーの場合は解答を実行しません。コンパイルには 120 秒の制限がありますが、`run` で起動した解答には時間制限を設けません。解答が 0 以外で終了した場合は終了コードを、終了コードが取得できない場合はその旨を表示します。

## 提出ソースの準備とコピー

問題ディレクトリで `ackit prepare [--no-test]` を実行すると、提出するソースを標準出力へ出します。ログとエラーは標準エラー出力へ出すため、`ackit prepare > submission.txt` のように保存できます。提出前コマンド、サンプルテスト、提出ファイルの読み込みは `submit` と共通です。ソースの改行は CRLF に正規化されます。失敗時にソースは出力しません。

`ackit copy [--no-test]` は同じソースを端末へ OSC 52 シーケンスとして送信します。端末の対応状況によってクリップボードへの保存結果は異なります。標準出力が端末でない場合は、提出前コマンドを実行する前にエラーになります。どちらのコマンドも `--no-test` でサンプルテストだけを省略し、提出前コマンドは実行します。

## 5. 提出
コードを提出するには、以下のコマンドを実行します。
```shell
ackit submit [--no-test]
```
- `--no-test`: 提出前のサンプルテストをスキップする場合に指定します。

（`--no-test` を指定しない場合）提出前にサンプルテストが行われ、すべてのサンプルケースを通過した場合に提出が行われます。
提出前コマンドが設定されている場合は、先にそのコマンドを実行し、生成・変換後の状態でサンプルテストを行います。`--no-test` を指定しても提出前コマンドは実行されます。

> [!IMPORTANT]
> AtCoder と Cloudflare Turnstile の仕様により、CAPTCHA 認証が要求されるコンテストでは提出できません。
> 
> 現在は、主に進行中のコンテストでのみ提出に対応しています。

提出が成功した場合、提出 URL が表示されます。

## 6. ログアウト
AtCoder-Kit からログアウトするには、以下のコマンドを実行します。
```shell
ackit logout
```
このコマンドを実行すると、AtCoder-Kit に保存されているログインセッションが削除され、ログアウト状態になります。
